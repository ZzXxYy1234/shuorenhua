# 说人话 (shuorenhua)

一个 ZCode 技能，做两件事：**把 AI 腔的文字改得直接自然**，以及**把术语密集的内容讲成人话、同时把名词教会**。

## 与其他"说人话"提示词 / 技能的区别

网上常见的"说人话"提示词，大多是把 AI 生成的文字**重新生成一遍**：整段润色、换一种口吻再写一次。本技能在三个地方走了不同的路：

**1. 编辑器，不是改写器。**
默认在原稿上做最小必要编辑：删套话、清翻译腔，但事实、判断、数字、条件、否定、情态一个都不能动——拿不准就保留原句，没有编辑收益就不改。改稿与原文逐句可对照，不是"按大意重写"。

**2. 可核对的交付，不打玄学分。**
支持"只标问题不改写"（列出问题片段+修改方向，正文原样保留）；不输出"AI 含量"评分这类无法验证的东西。程序代码块默认原位保留，注释不经授权不进编辑。

**3. 不消灭术语，而是教会术语（最大的差异点）。**
常见工具的目标是把术语**翻译掉**，讲完就完。本技能的术语绑定讲解模式反其道而行：**面向持续学习**——对方后续还要反复阅读这个领域的汇报，所以每个术语用"大白话（术语）"成对绑定、全篇锚点一致、结尾附记忆卡（术语 | 大白话 | 一句话记忆）、项目场景维护常驻术语对照表。目标是：第一次听懂，第二次认识，第三次直接读术语。

一句话：**别的"说人话"是把术语藏起来，这个是把术语变成用户 Vocabulary 的一部分。**

另外它不是一段裸提示词，而是结构化技能：主流程 + 按需参考文件 + 验收清单 + 真实案例回归实测记录 + git 版本管理；模式从真实项目（PandaAI 因子大赛的持续学习场景）抽象而来，失败模式（"只讲人话不点术语" / "只报术语不解释" / "锚点漂移"）都吃过一遍才写进规则。

## 两种模式

### 1. 审稿 / 去 AI 味

清理套话、填充与翻译腔，保留事实、判断、数字与责任主体。

- 三档编辑范围：`structural`（可删并重排）/ `bounded`（不删整句）/ `in-place`（只句内替换）
- 支持**只标问题不改写**（annotation mode）
- 程序代码块默认原位完整保留，注释不经授权不进编辑

触发方式：对 ZCode 说「说人话」「去 AI 味」「只标问题」「审一下这段」。

### 2. 术语绑定讲解（面向持续学习）

核心规则四条：

1. **双轨绑定**：术语首现按"大白话（术语）"成对给出，此后全篇直接用术语
2. **锚点一致**：同一术语不中途换大白话说法
3. **记忆卡收尾**：附三列表格 `术语 | 大白话 | 一句话记忆`，覆盖全部新术语
4. **常驻对照表**：项目场景下记忆卡写入常驻术语表文件，新词追加、旧词留存

触发方式：对 ZCode 说「用术语绑定的方式讲讲 XX」「讲成人话，但我要记住这些名词」。

## 验收

术语绑定模式带 5 项验收清单（首现绑定 / 锚点一致 / 记忆卡一一对应 / 小白双向测试 / 常驻对照表更新）。回归实测见 `references/term-binding-test.md`：输入为一段用户实际反馈"看不懂"的原文，转换后 5 项全过。
